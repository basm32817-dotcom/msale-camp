# 🎓 نظام تسجيل الطلاب في المعسكر — الأستاذ علي ضاحي (الحاكم)

نظام ويب احترافي بالعربية (RTL) لتسجيل الطلاب في معسكر الدرس، مع توليد ملف PDF لكل طالب وإرساله إلى واتساب الإدارية عبر **WhatsApp Cloud API الحقيقي** (وليس بأي طريقة وهمية).

---

## ✨ المزايا

- ✅ استمارة تسجيل عربية بالكامل (RTL) — الاسم، رقم الهاتف، المرحلة الدراسية، المكان.
- ✅ المرحلة الدراسية: **أولى ثانوي / ثانية ثانوي / ثالثة ثانوي فقط**.
- ✅ تحقق كامل من البيانات (من المتصفح، ومن الخادم عند توافره).
- ✅ **☁️ ربط سحابي بـ Firebase**: تسجيلات كل الهواتف تتجمع في مكان واحد مهما كان الجهاز.
- ✅ حفظ دائم (سحابي → خادم → احتياطي محلي، تسلسلًا تلقائيًا ومزامنة ذاتية).
- ✅ توليد **ملف PDF منظم** يحتوي كل بيانات الطالب + اسم الأستاذ + اللقب + تاريخ ووقت التسجيل.
- ✅ رسالة نجاح: **تم تسجيل الطالب بنجاح ✅** + تحميل PDF + إرساله إلى واتساب الإدارية.
- ✅ لوحة إدارة: جدول الطلاب، البحث بالاسم أو رقم الهاتف، عدد الطلاب، تسجيلات اليوم، PDF لكل طالب، إرسال واتساب، حذف.
- ✅ تصميم شبابي هادئ، متجاوب مع الهاتف والكمبيوتر.

## 🚀 التشغيل

1. ثبّت Node.js (نسخة 18 فما فوق).
2. افتح المجلد في الطرفية (Terminal) ونفّذ:

```bash
npm install
npm start
```

3. افتح المتصفح:

| الصفحة | الرابط |
|---|---|
| استمارة التسجيل | http://localhost:3000 |
| لوحة الإدارة | http://localhost:3000/admin |

## 🌍 النشر في كل مكان (GitHub Pages + Firebase) — مجاني ودائم

هذا هو الحل المعتمد لجعل رابط التسجيل **يعمل من أي هاتف في أي مكان** مع تجمّع كل التسجيلات في مكان واحد:

- **GitHub Pages** يستضيف الصفحات من الإنترنت (الرابط يعمل دائمًا: `https://<اسمك>.github.io/<اسم-المشروع>/`).
- **Firebase Realtime Database** (مجانية من Google) تجمع تسجيلات كل الهواتف في قاعدة واحدة يراها كل الأجهزة واللوحة.

### الخطوة 1 — إنشاء حساب GitHub ومستودع
1. سجّل في [github.com](https://github.com) (مجاني).
2. أنشئ مستودعًا جديدًا باسم مثل `msale-camp` (Public أو Private، أيًا كان).
3. لا تضيف أي ملفات تلقائية — فقط أنشئ المستودع الفارغ.

### الخطوة 2 — إنشاء مشروع Firebase (5 دقائق)
1. ادخل إلى [console.firebase.google.com](https://console.firebase.google.com) وسجّل بحساب Google.
2. اضغط **إضافة مشروع** → سمِّه مثل `msale-camp` → تابع (بدون Google Analytics).
3. من شاشة المشروع اضغط **أيقونة الويب `</>`** لإنشاء تطبيق ويب، وسمِّه مثل `msale-web` ثم انسخ كتلة **firebaseConfig**.
4. من القائمة الجانبية اذهب إلى **Build → Realtime Database** → **إنشاء قاعدة بيانات** → اختر منطقة قريبة (مثل `europe-west1` أو `asia-southeast1`) → **وضع الاختبار**.
5. في تبويب **Rules** الصق محتوى ملف `firebase.rules.json` (قواعد قراءة/كتابة مفتوحة):

```json
{ "rules": { ".read": true, ".write": true } }
```

### الخطوة 3 — وضع مفاتيح Firebase في المشروع
افتح `public/js/config.js` واستبدل القيم النصية `ضع-...` بكل قيمة من كتلة **firebaseConfig** التي نسختها من Firebase، مثلًا:

```js
FIREBASE_CONFIG: {
  apiKey: 'AIzaSyAbCdEfGhIjKlMnOpQrStUvWxYz',
  authDomain: 'msale-camp.firebaseapp.com',
  databaseURL: 'https://msale-camp-default-rtdb.europe-west1.firebasedatabase.app',
  projectId: 'msale-camp',
  storageBucket: 'msale-camp.appspot.com',
  messagingSenderId: '1234567890',
  appId: '1:1234567890:web:abcdef123456',
}
```

> القيم أعلاه مثال فقط — انسخ قيمك الحقيقية من Firebase.

### الخطوة 4 — رفع الكود إلى GitHub والنشر
في الطرفية داخل مجلد المشروع:

```bash
git init
git add .
git commit -m "Camp registration system - MS.ALE"
git branch -M main
git remote add origin https://github.com/<اسمك>/<اسم-المستودع>.git
git push -u origin main
```

(عند أول push سيطلب git بيانات الدخول إلى GitHub — أدخلها أو استخدم GitHub Desktop لتسهيل الأمر.)

### الخطوة 5 — تفعيل النشر من GitHub Actions
1. من صفحة المستودع على GitHub: **Settings → Pages**.
2. تحت **Source** اختر **GitHub Actions** (وليس Deploy from a branch).
3. البيانات ستنشر تلقائيًا من ملف `.github/workflows/deploy.yml`.

### النتيجة 🎉
- رابط التسجيل للطلاب: `https://<اسمك>.github.io/<اسم-المشروع>/`
- لوحة الإدارة: `https://<اسمك>.github.io/<اسم-المشروع>/admin.html`
- كل تسجيل من أي هاتف يظهر مباشرة في اللوحة (بفضل Firebase).
- لا يشترط تشغيل جهازك أو الخادم — الرابط يعمل 24 ساعة.

> 💡 **في واتساب:** الرابط `https://...` سيظهر نابضًا وقابلًا للنقر تلقائيًا — بعكس `localhost` الذي كان يصل كنص فقط.

> ✅ **مضبوط حاليًا على:** الرقم المصري `+20 10 06899642` (بصيغة `201006899642`) — يُرسل إليه ملف الـPDF في `public/js/config.js` وفي `.env`.

**لتغيير الرقم لاحقًا — الخطوة 1 (الواجهة):** افتح `public/js/config.js`:

**الخطوة 2 — في الخادم:** إن لم يوجد ملف `.env` انسخ الإعدادات ثم عدّل الرقم:


> إذا كان الخادم يعمل، يُقدَّم رقم ملف `.env` تلقائيًا على رقم الواجهة.
> الصيغة المطلوبة: رمز الدولة + الرقم بدون `+` أو مسافات أو أصفار بادئة مكررة.

## 📲 الربط الحقيقي مع واتساب (WhatsApp Cloud API)

إرسال ملف PDF **الفعلي** إلى واتساب يتطلب **WhatsApp Cloud API** من Meta (لا يمكن إرسال ملفات من متصفح مباشرة إلى واتساب بشكل آلي). المشروع **جاهز للربط** بالكامل، والتنفيذ في `src/whatsapp.js` يستخدم الواجهة الرسمية:

1. رفع ملف الـPDF إلى وسائط واتساب: `POST /{PHONE_NUMBER_ID}/media`
2. إرساله كرسالة مستند: `POST /{PHONE_NUMBER_ID}/messages`

### الخطوات للحصول على التوكن

1. أنشئ تطبيقًا على [developers.facebook.com](https://developers.facebook.com) → إضافة منتج **WhatsApp**.
2. من **WhatsApp → API Setup** احصل على:
   - **توكن الوصول** (`WHATSAPP_ACCESS_TOKEN`)
   - **معرّف رقم الهاتف** (`WHATSAPP_PHONE_NUMBER_ID`)
3. ضع القيم في ملف `.env`:

```
WHATSAPP_ACCESS_TOKEN=EAAxxxx...
WHATSAPP_PHONE_NUMBER_ID=1234567890...
WHATSAPP_API_VERSION=v21.0
```

4. أضف رقم الإدارية كرقم مسموح به في لوحة Meta (Test numbers) أو استخدم حسابًا مُفعّلًا.

### سلوك النظام

| الحالة | ماذا يحدث عند الضغط على «إرسال إلى واتساب» |
|---|---|
| الخادم مربوط بالكامل | ✅ يرفع الملف ويرسله فعليًا إلى رقم الإدارية (إرسال آلي) |
| الخادم يعمل لكن التوكن غير مضبوط | ⚠️ تظهر رسالة واضحة بالسبب + تُفتح محادثة واتساب مع الإدارية لإرفاق الملف يدويًا |
| الخادم غير متاح | ⚠️ يُفتح تطبيق واتساب مع نص التسجيل كاملًا والإرشاد بإرفاق الـPDF يدويًا |

> **لا توجد أي رسالة إرسال وهمية**: إن لم يُرسل فعليًا، يصرّح النظام بذلك ويعرض البديل الصادق.

## 🔑 لوحة الإدارة

- `http://localhost:3000/admin`
- عرض كل الطلاب: الاسم، رقم الهاتف، المرحلة، المكان، تاريخ التسجيل.
- البحث الفوري بالاسم أو رقم الهاتف.
- عدد الطلاب المسجلين + تسجيلات اليوم.
- لكل طالب: إنشاء/تحميل PDF، إرسال إلى واتساب، حذف.

> ملاحظة: لوحة الإدارة مفتوحة بدون كلمة مرور (للاستخدام الداخلي). بعد النشر على جت هب، أي شخص يملك الرابط يستطيع فتحها - استخدم رابطًا معقدًا للمشروع أو أضف حماية لاحقًا إن رغبت.

## 🗂️ البيانات

- **بعد النشر على جت هب:** كل التسجيلات تتجمع في **Firebase Realtime Database** — تظهر في لوحة الإدارة من أي جهاز (نسخ احتياطية متاحة من لوحة Firebase).
- **مع الخادم المحلي:** تُحفظ البيانات في `data/students.json` — لا تحتاج قاعدة بيانات.
- **بدون أي خادم:** يُحفظ التسجيل محليًا في المتصفح احتياطًا، ويُرفع تلقائيًا للسحابة عند أول اتصال.
- للانتقال إلى قاعدة بيانات أخرى لاحقًا، عدّل فقط `src/store.js` أو طبقة `Storage` في `public/js/storage.js`.

## 🛠️ ملاحظات تقنية

- ملفات PDF تُولَّد في المتصفح بجودة عالية عبر `html2canvas + jsPDF` — النص العربي يظهر بشكل صحيح 100% بدون مشاكل الخطوط.
- الخادم يتحقق من البيانات مرة ثانية قبل الحفظ (أمان إضافي).
- الحد الأقصى لحجم ملف الـPDF المرفوع إلى الخادم: 15 ميجابايت.
